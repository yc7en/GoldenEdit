# R-261028-0001 · 架构重写与文档基线重建

## 一、变更背景与原因

原实现基于 Go + Wails v2，已完成 Monaco 编辑器、三布局、文件树、多标签与七个内置插件的原型（见 `GoldenEdit.7z` 归档）。继续演进前遇到三个结构性问题：

1. **资源加载方式不可移植**：自定义协议在沙箱 iframe 场景下的行为不一致，图片与字体加载不稳定，且 CSP 不在自己手里。
2. **插件契约过宽**：早期设计把 `markdown-it` 实例直接交给插件，等于给出全权；同时未规定锚点归属，第三方插件一旦自行渲染就会丢掉 `data-line`，跳转功能随之失效。
3. **性能策略缺失**：全量 `innerHTML` 替换导致图表重绘、折叠状态丢失、滚动跳变，文档变大后不可用。

因此不是修 bug，而是重新确定架构基线：换壳（Rust + Tauri 2）、改隔离模型（预览迁入独立源 iframe）、重定义插件契约、补齐四层性能策略。前端渲染资产可复用，后端与绑定层重写。

## 二、变更具体内容

### 2.1 分层与隔离

- 确立三层：Rust 宿主（不解析 Markdown）/ 主 WebView（唯一持有 IPC）/ 预览 iframe（opaque origin，无 IPC）。
- 预览外壳页由本地 HTTP 服务提供，**不得使用 `srcdoc`**，避免继承父页面源导致沙箱失效。
- 插件代码只在预览 iframe 内执行，永远拿不到宿主 DOM 与 IPC。

### 2.2 资源加载

- 废弃 `asset://`，改由 `127.0.0.1:0` + 随机 token 的本地服务提供外壳、插件资源与 vault 内图片字体。
- CSP 由该服务自行下发，插件脚本以真实 URL 加载，不再需要 Blob 注入。

### 2.3 插件契约

- `ctx` 收窄为 `env / config / doc / theme / onFence / onContainer / onDelimiter / onMount / assets / libs / log`。
- 块包裹、`data-line`、错误卡片由管线生成，插件不得输出外层结构与锚点。
- 明确双环境约定：同一份 `entry.js` 在 Worker 与主线程各执行一次 `register`，用 `ctx.scope` 分支。
- 能力分级 L0–L3 按运行时访问记录判定。

### 2.4 渲染管线

- 块级 morphdom + 块 key（源码 + 插件版本 + 主题模式）。
- 首屏 200 块分片渲染，其余空闲追加。
- 150ms 防抖 + 代际号丢弃过期批次。
- Worker 内完成解析与 L1 渲染，L2 块回主线程 mount。
- 按文档大小分四档降级，>10MB 自动暂停预览。

### 2.5 交互与主题

- 文件树常驻、大纲浮层抽屉、预览可收成 34px 把手。
- 分栏比例按文件记忆，存应用数据目录。
- 预览只读，行号角标点击跳源码，正文保持原生选区。
- 主题四档预设，编辑器与预览可独立，插件强制使用 `--ge-*` 变量。

### 2.6 导出

- HTML 由前端生成（与预览共用同一段渲染代码），Rust 仅落盘。
- PDF 在 Windows 走 WebView2 `PrintToPdfAsync` 静默输出，其它平台降级为打印对话框。
