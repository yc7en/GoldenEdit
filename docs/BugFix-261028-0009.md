# BugFix-261028-0009 · 预览沙箱缺少 allow-modals，PDF 导出静默失效

## 缺陷描述

在导出对话框里选择 PDF，确认保存路径后：

- 没有报错、没有 toast 失败提示；
- 也没有弹出系统打印对话框；
- 保存路径上什么都没生成。

控制台里只有一行容易被忽略的提示：

```
Ignored call to 'print()'. The document is sandboxed and lacks the 'allow-modals' flag.
```

**根本原因**：预览 iframe 的 `sandbox` 只声明了 `allow-scripts allow-same-origin`。
按 HTML 规范，不含 `allow-modals` 的沙箱文档中 `window.print()`、`alert()`、`confirm()` 一律被丢弃且**不抛异常**。
而 PDF 一期正是走「L3 内 `window.print()` → 用户在打印设置里另存为 PDF」这条链路（ARCHITECTURE §9.5），
于是整条路径在没有任何错误信号的情况下失效——这比报错更糟，因为它看起来像「点了没反应」。

## 修复方法与实现

1. **沙箱补 `allow-modals`**：
   - [frontend/index.html](file:///j:/CODE/GoldenEdit/frontend/index.html) 的预览 iframe 改为
     `sandbox="allow-scripts allow-same-origin allow-modals"`。
   - 风险评估写入 [docs/ARCHITECTURE.md](file:///j:/CODE/GoldenEdit/docs/ARCHITECTURE.md) §11.1 第 5 条：
     代价是插件代码可以弹模态阻塞界面；但文档内嵌 `<script>` 在渲染阶段已被 `stripScripts` 剥离，
     外来 HTML 无法借此弹窗，而插件本身本来就能改 DOM。可接受。

2. **拒绝静默失败**：
   - [src-tauri/src/commands/export.rs](file:///j:/CODE/GoldenEdit/src-tauri/src/commands/export.rs) 的 `export_pdf`
     继续返回 `PRINT_FALLBACK`，并补注释说明「Tauri 2 未暴露 PrintToPdfAsync 的直接入口」；
   - 前端在收到 `PRINT_FALLBACK` 时会 `preview.requestPrint()` 并提示「已打开打印对话框，请选择另存为 PDF」，
     用户至少知道下一步该做什么。

3. **文档与实现对齐**：
   - ARCHITECTURE §9.5 原先写的是「Windows 走 `ICoreWebView2_7::PrintToPdfAsync` 静默输出」，
     那是计划而非实现。本次改为如实描述「打印对话框 + `@page` A4」，
     并把静默输出（隐藏 WebView + `ICoreWebView2_16::PrintToPdfAsync`）明确列为二期，
     附上不做的理由：收益（少一次点击）小于成本（第二个 webview 的生命周期、文件服务路由、跨进程时序）。

## 影响范围

- 仅影响「导出 PDF」与任何依赖 `window.print()` 的路径；预览渲染本身不受影响。
- 沙箱能力扩大一项（`allow-modals`），其余防线不变：跨源、无 IPC、CSP 未变。

## 验证方式

1. `npm run build` 后启动应用，选中含表格与代码块的文档 → `Ctrl+E` → 选 PDF → 确认路径；
2. 应弹出系统打印对话框，且预览内容为文档本身（不含应用界面、不含行号角标）；
3. 在打印设置里选「另存为 PDF」并保存到刚才的路径，生成的文件可正常打开；
4. 控制台不再出现 `Ignored call to 'print()'`。
