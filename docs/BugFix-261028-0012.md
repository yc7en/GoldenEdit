# BugFix-261028-0012 · 预览冻结：代际号错位 + 解析异常不回包

## 缺陷描述

性能验收改成进程内驱动后，脚本每次都报同一个错：

```
应用内验收中断：渲染超时
```

应用本身看起来是好的：窗口在、预览服务在（`http://127.0.0.1:10858`）、文档也渲染过。
现场日志里只有一条与冻结无关的插件告警。再往下排查，发现两个独立缺陷叠在一起。

## 缺陷一：宿主与外壳各持一个代际号，会错位

`PreviewHost` 与预览外壳（iframe）各自维护 `gen`：

- 宿主：`push()` 时 `gen += 1`，并把 `renderWaiter.gen` 绑到这次号码；
- 外壳：`requestRender()` 时 `gen += 1`，用它给 Worker 发任务，再把 Worker 结果里的 `gen` 原样回传。

正常情况下两边同步递增，能对上号。但**外壳在主题变更、重挂时也会 `requestRender()`**，
宿主那边却没有 `push`，于是外壳多加了号，此后永远差 N 个：

```
外壳 gen = 4  →  rendered.gen = 4
宿主 gen = 2  →  renderWaiter.gen = 2   永远等不到
```

同一处还有第二个坑：文档在握手中途到达时，外壳只记住 `lastText`、丢掉 `msg.gen`，
握手完成后用自己从 0 开始的号补发，同样对不上。

## 缺陷二：解析抛异常不回 `result`，预览永久冻住

Worker 的 `self.onmessage` 只有一个外层 `try/catch`，任何异常都变成一条 `fatal` 消息，
**不会回 `result`**。宿主那边等的是 `rendered`，于是一次解析失败就等于：

- 状态条永远卡在「渲染中」；
- 之后的每一篇文档都不再出图（Worker 还活着，但没人再消费它的输出）。

实测触发点是一条 inline 规则在静默模式下返回 `true` 却没有推进 `state.pos`，
markdown-it 抛出 `inline rule didn't increment state.pos`。

## 修复方法与实现

1. **代际号由宿主统一发号，外壳原样带回**
   - [frontend/preview-shell/shell.ts](file:///j:/CODE/GoldenEdit/frontend/preview-shell/shell.ts)：
     `requestRender(text, hostGen?)`——`doc` 消息带的号直接采用；主题变更 / 重挂这类外壳自发
     渲染复用 `lastGen`，**不再自行加号**；
   - 握手中途到达的文档连号一起记（`lastGen`），唤醒后原号补发。

2. **宿主侧把等待位绑号收口到一个入口**
   - [frontend/src/preview/host.ts](file:///j:/CODE/GoldenEdit/frontend/src/preview/host.ts)：
     新增 `nextGen()`，`push()` 与 `init()` 补发首渲染都走它。原先 `init()` 是裸 `gen += 1`，
     「握手前就订阅了渲染完成」的等待位永远绑不上号。

3. **解析失败也要回包**
   - [frontend/preview-shell/worker/parse.ts](file:///j:/CODE/GoldenEdit/frontend/preview-shell/worker/parse.ts)：
     `doc` 分支单独 `try/catch`，失败时照样 post 一条 `result`（空 blocks + 一条 error + 原始字符数），
     并额外 post 一条 log。预览会清空并显示错误，但**不会冻结**，下一篇文档照常渲染。
     外层 `try/catch` 仍负责 `init` / `expand` 的致命错误。

## 影响范围

- 代际号错位影响「任何会触发主题重渲染的路径」：切主题、改自定义 CSS、切明暗、重挂插件后，
  宿主对「渲染完成」的判断会整体失准（性能探针必然超时，状态条也可能一直转圈）。
- 回包兜底影响所有解析失败场景：以前是一次失败整场报废，现在是单篇降级。

## 验证方式

1. `node scripts/perf-check.mjs` 三档能跑完并打印结果（修前一律「渲染超时」）；
2. 在应用里连切三次主题，再打开一个大文件，状态条应正常从「渲染中」回到块数；
3. 故意让某个插件在 `render` 里抛错，预览应显示错误块，且切换另一个文件后能正常渲染。
