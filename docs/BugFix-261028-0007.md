# BugFix-261028-0007 · 打开文件夹后无法列举文件及插件目录探测增强

## 缺陷描述

1. **打开文件夹后左侧栏看不到任何文件**：
   用户点击「打开文件夹」选择工作区后，左栏文件树显示为空或保持未加载状态。
   根本原因是：后端 `open_vault` 会调用 `list(&root, "")` 读取首层条目，而 `paths::resolve_in_vault(root, rel)` 内部无差别调用 `validate_rel(rel)`。`validate_rel` 将空字符串 `""` 判定为非法空路径并抛出 `DENIED` 错误，导致 `open_vault` 以及后续前端 `list_dir("")` 调用必定失败，文件列表永远无法返回给前端渲染。此外，Windows 下 `Path::strip_prefix` 严格区分大小写，若盘符或路径存在大小写差异会导致条目相对路径解析为 `None` 而被静默丢弃。

2. **从不同路径启动时扫描不到内置插件**：
   用户从 `target/debug/` 或外部工作目录直接运行 `goldenedit.exe` 时，原 `builtin_roots()` 仅向上查找 2 层相对路径，无法定位到项目根目录与 `frontend/plugins`，导致应用内插件列表显示为 0。

## 修复方法与实现

1. **工作区根路径解析放行**：
   - 修改 [src-tauri/src/paths.rs](file:///j:/CODE/GoldenEdit/src-tauri/src/paths.rs) 中的 `resolve_in_vault`：当 `rel` 为空字符串或 `.` 时，直接解析并返回工作区根目录的规范化绝对路径 `canon_root`，满足根目录遍历需求；
   - 改进 `to_rel` 算法：按路径段逐级对比，并在 Windows 系统下采用忽略大小写的匹配，防止因 Windows 盘符或路径大小写不一致导致相对路径转换失败；
   - 增加对应单测 `resolve_in_vault_allows_root_itself` 与 `to_rel_handles_case_difference_on_windows`。

2. **内置插件目录回溯增强**：
   - 修改 [src-tauri/src/commands/plugin.rs](file:///j:/CODE/GoldenEdit/src-tauri/src/commands/plugin.rs) 中的 `builtin_roots`：增加从 `current_exe()` 逐级向上回溯 6 层探测逻辑，兼容直接从 `target/debug/` 或其他嵌套目录启动时的内置插件扫描；
   - 在项目根目录创建 `plugins` 目录软链接/Junction 指向 `frontend/plugins`，确保在根目录与 `frontend/` 下均能直观看到插件源码；
   - `.gitignore` 忽略根目录符号链接 `plugins/`，避免 git 索引冲突。

3. **前端文件树渲染与层级缩进**：
   - [frontend/src/ui/shell.ts](file:///j:/CODE/GoldenEdit/frontend/src/ui/shell.ts) 增加文件树递归深度缩进（`depth * 14px`），并在目录确实为空时提示「当前文件夹为空」，避免无任何提示的空白现象。
